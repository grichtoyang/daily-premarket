# V9 Pro Dashboard 單位標準

版本：1.1  
適用：六頁 Dashboard、DATA_REPORT、Python Builder、分析文字及圖表。

## 1. 三層單位契約

每個數值欄位必須同時定義：
1. **來源單位**：DATA_REPORT 或 API 原始資料實際提供的單位。
2. **Builder 標準單位**：Python 解析、計算後保留的單位；轉換必須有明確公式。
3. **Dashboard 顯示單位**：KPI、表格、文字、圖表的使用者可見單位。

不得依數值大小猜測單位；來源未定義時標記 BLOCKED，不得自行加上推測單位。不得把百分比與百分點、價格與漲跌點數、成交量與未平倉量混為一談。

## 3. 正負號、存量／流量與衍生指標語義

- 法人買賣超：正值為買超、負值為賣超；金額與口數不可混為同一量綱。
- OI（未平倉量）是某一時點的部位存量；日盤／夜盤淨交易是區間流量。不得將 OI 與單日淨交易直接相減並解讀成「對作口數」。
- PCR 固定為 Put OI ÷ Call OI，單位為倍；成交量占比是另一指標，單位為 %。
- GEX 是 OI-based Black-Scholes 模型估值。公式中的 Call／Put 正負號是模型假設，不代表已知造市商真實持倉；GEX 正負不得直接轉成 Bias 多空分數。
- 技術指標的歷史序列、歷史相似度、因子勝率及相關性均須以報告 T0 作為 as-of 截止；不得使用 T0 之後的行情或已知結果。
- 歷史相似樣本的隔日上漲／下跌比例是結果分布，不等於策略勝率；只有定義方向、進出場及損益規則後，才可計算策略勝率。
- Regime／因子文字必須直接對應程式實際使用的門檻；不得使用「月線突破」「創高」「支撐防線」等未計算或未驗證的術語。
- 技術指標若資料筆數不足其計算需求，該指標應停用或標示 unavailable，不可使用零值替代。
- 因子狀態必須區分「缺值」與「有值但不參與方向評分」；例如 GEX 可正常顯示模型值，但在沒有方向化規則時屬 disabled，不應列入 missing。

## 4. 顯示規則

- KPI、表格、一般文字：數字旁必須有單位；同欄表頭已清楚定義單位時，欄內可不重複。
- 圖表：優先在軸標題、圖例或數列名稱標單位。
- 圖內數字標籤若加單位會造成擠壓、裁切、遮擋或可讀性下降，可省略逐筆單位，改在圖表緊鄰的上方或下方加明確備註，例如「單位：口」「價位單位：點」。
- 混合單位圖表必須逐數列標示單位；不得用一個籠統備註涵蓋不同量綱。
- 縮放數值必須標示轉換方式，例如「圖示值為原始口數 ÷ 1,000（千口）」；不得只寫 x10 而不說明原始量及換算方向。
- 不得因單位標籤造成文字與圖示重疊；優先使用圖表外備註，不得硬塞進每個資料標籤。
- 桌面及手機寬度均須驗證換行、裁切、圖例、數值標籤及文字／圖示重疊。靜態程式檢查不能取代實際渲染驗收。

## 5. 資料缺失與驗證

- 缺值顯示 unavailable；不得以 0 代替缺值。
- 每個欄位須定義來源、來源單位、標準單位、顯示單位、精度、正負號意義及衍生公式。
- 任何單位轉換須有測試覆蓋，至少驗證轉換方向、倍率、負值及 unavailable。
- DATA_REPORT 解析器須驗證單位字串；只擷取數字而忽略單位的欄位不得標記為來源單位驗證 PASS。
- GEX 單位依 Worker 生產公式與 DATA_REPORT 14A 確認為 NT$／標的價格變動 1%；模型品質與覆蓋狀態仍須另行呈現，不得稱為 TAIFEX 官方數據。

## 6. 驗收狀態

PASS：來源、Builder、Dashboard 單位一致，且測試涵蓋。  
FAIL：已確認單位錯誤、缺漏或欄位契約不一致。  
BLOCKED：上游定義或來源單位尚未確認。  
NOT TESTED：尚未執行實際測試或桌面／手機渲染。
