# V9 Pro — Visual Layer Skill（正式版）

版本：1.0｜定版日期：2026-11-14
正式頁面：總覽、現貨、重要市場、期貨、選擇權、綜合分析。

## 1. 視覺層職責

視覺層只負責把既有 Dashboard JSON 與分析文字呈現為清楚、可讀、可操作的六分頁 Dashboard。不得在 UI 層擷取資料、修改資料語義或用假值填補缺值。

主要檔案：
- Template：\`templates/v9-pro-react-template.html\`
- Builder：\`scripts/v9_pro_builder.py\`（資料層凍結期間只讀）
- Unit Map：\`docs/DASHBOARD_UNIT_MAP.md\`
- Unit Standard：\`docs/DASHBOARD_UNIT_STANDARD.md\`
- Browser Audit：\`tests/browser_dashboard_audit.mjs\`

## 2. 固定視覺原則

- 保留原 V9 Pro 視覺風格、深色系、卡片層級、資訊密度及六頁導覽。
- 不另建新 Dashboard Template，不擅自重新設計期貨頁或其他已驗收頁面。
- 保持既有分頁順序與功能；不刪除、合併或移動其他頁面，除非使用者明確要求。
- 文字層級清楚，標題、圖表、表格與分析文字不互相擠壓。
- 避免過度留白、過窄卡片、過長標題及不必要的雙欄排列。
- 新聞清單使用足夠寬度，避免摘要文字被壓縮。
- 不因追求視覺一致而讓不同單位或不同市場資料共用含糊圖例。

## 3. 顏色與圖表語義

台股顏色慣例：
- 紅色：上漲／多方。
- 綠色：下跌／空方。

顏色必須對應數據方向，不可單純依卡片位置或視覺裝飾決定。中性、缺值與不可判讀狀態不得偽裝成多空訊號。

圖表要求：
- 圖表數字必須來自 Dashboard data payload 或明確的 UI 呈現計算。
- 圖表與文字不得出現不同數值或不同基準。
- 價格線、成交量、法人流量、OI、模型估值等不同量綱不得共用無說明的座標或圖例。
- 圖表需提供可讀標籤、基準、日期及單位說明。
- 缺值顯示 unavailable；不可畫成 0、假線或假支撐。
- 多日圖必須有日期對應，不能把不連續樣本畫成連續等距交易日而不說明。

## 4. 單位契約

以 \`docs/DASHBOARD_UNIT_STANDARD.md\` 及 \`docs/DASHBOARD_UNIT_MAP.md\` 為準：

- 指數／期貨／價位：點。
- 漲跌幅／殖利率水準：%；殖利率變化：pp。
- 現貨法人金額／成交金額：億元。
- 融資餘額：億元；融券、借券：張。
- 期貨／選擇權成交量、OI、交易口數：口。
- PCR：倍，固定 Put OI ÷ Call OI。
- Bias：分；因子數：項。
- GEX：NT$／標的價格變動 1%，且須標示為模型估值。

KPI、表格及一般文字必須標示單位；圖表可在軸、圖例或緊鄰註記標示。若逐筆標籤加單位造成擁擠，可移至圖表旁註；混合單位圖表必須逐序列標示。

## 5. 六分頁 UI 邊界

- 總覽：重大新聞區塊已移除，避免與重要市場重複；保留 KPI、Bias、五日趨勢、法人快照、期選結構及美股連動等決策摘要。
- 現貨：保留 A–F 分析結構與既有視覺語言；成交結構、廣度、法人及槓桿資訊不可用錯誤圖表或色彩誤導。
- 重要市場：重大新聞依 DATA_REPORT 第 8 節呈現，重大新聞卡片全寬；商品區塊維持適當寬度。
- 期貨：保留已驗收的原 V9 版型與日／夜盤、基差、OI、流量及劇本資訊。
- 選擇權：保留已驗收的選擇權結構與分析區塊；不得把成交量、OI、PCR、法人流量與 GEX 混成同一口徑。
- 綜合分析：保留決策導航、跨市場比較、因子與日夜盤檢查、三劇本及交易計畫；不複製各專業分頁全文。

## 6. 響應式與可讀性

至少檢查：
- Desktop：1440px。
- Tablet：1024px。
- Mobile：390px。

逐頁檢查：
- 文字換行、卡片高度、裁切、重疊及水平溢位。
- 圖例、座標、單位、數值標籤是否完整。
- 重要資訊是否因欄寬而被截斷。
- 互動分頁切換後內容是否更新，無空白頁或 JavaScript 錯誤。
- 手機畫面需以實際頁面截圖確認；瀏覽器自動化通過不取代使用者人工視覺驗收。

## 7. 修改邊界與回歸

- 使用者指定只改某一分頁時，只能改該分頁及必要共用程式；其他分頁需列入回歸保護。
- 已驗收分頁視為凍結。除非有新證據或使用者明確授權，不得主動調整。
- 修改共用元件前先確認所有分頁受影響範圍。
- 檢查 diff，確認沒有碰到 Builder、DATA_REPORT、資料來源、Worker、Proxy、daily-data Workflow 或其他未授權檔案。
- Template Push 可能觸發 Build + Deploy Workflow；推送前必須檢查 Workflow path filter 與執行內容。

## 8. 視覺驗收

PASS：
- 六分頁內容能正常顯示，無 JS 錯誤、無水平溢位。
- 單位與數值對應正確，缺值呈現清楚。
- Desktop／Tablet／Mobile 版面可讀。
- 使用者指定範圍完成，其他頁面無回歸。
- 使用者完成實際畫面驗收。

若只有 Playwright 或靜態檢查通過，僅能標示自動化／技術驗證 PASS；使用者視覺驗收仍需獨立標示。
