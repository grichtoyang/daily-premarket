# 台股每日盤前分析 Skill — V9 Pro

## 1. 專案與工作原則

- 本 Skill 僅適用於 **V9 Pro**；不得自行升版、改名或回退 V8。
- 以目前分支的程式、資料與 Workflow 為準；文件描述若與實際行為不同，先查證並回報，不可猜測。
- 修改前確認分支、檔案、Git 狀態、影響範圍及驗收方式。
- 僅處理使用者指定範圍；不得順手重構、擴大修改或重開已結案項目。
- 不得捏造資料、來源、計算結果、測試證據或完成狀態。
- 不得將估算、代理值、缺值、未測試功能描述成真實或已驗證結果。

## 3. 固定頁籤與修改邊界

V9 Pro 保留六個頁籤：總覽、現貨、重要市場、期貨、選擇權、綜合分析。

- 保留既有 V9 Pro 視覺風格與資訊架構；未經明確要求不得改版、刪除或合併頁籤。
- 修改限定在使用者指定分頁及其必要的 UI／分析程式；不得影響其他頁籤。
- 已驗收並由使用者要求凍結的分頁，不再主動修改；只有新證據顯示數據錯誤、邏輯矛盾、顯示回歸或使用者明確授權時才重開。
- 不因「還能潤飾」而持續修改；以實際錯誤、可讀性障礙、分析缺口或操作風險作為修改依據。

## 4. 資料層凍結（強制）

資料層目前為 **DATA LAYER FROZEN**。除非使用者事前明確授權特定項目，否則不得修改：

- 資料來源、端點、擷取、解析、清洗、轉換、計算、合併、fallback、缺值處理及輸出。
- Builder、DATA_REPORT 欄位／格式／單位／產出規則及資料層測試。
- daily-data Workflow、排程、觸發參數、重試、timeout、依賴及 commit/push 流程。
- Worker、Proxy、API、資料來源設定及任何會改變資料內容或取得方式的設定。

只讀檢查、讀取日誌、比對報告及提出修正方案不等於取得修改授權。發現疑似問題時，先提供證據、影響範圍及最小修正方案，等待使用者明確同意。授權僅限明確指定範圍。

資料層凍結期間，分析層只能使用 Dashboard 已有資料欄位改善判讀與呈現；不得為了補足敘事新增資料擷取或改動資料層。

## 5. 分析文字的統一標準

適用於六個頁籤所有分析／判讀／操作區塊。每個區塊依資料性質呈現三層，不得為了格式而重複數字或硬湊交易建議。

### 分析｜發生什麼事

- 說明實際數據、比較基準、時間範圍及單位。
- 解釋數據反映的市場現象與重要性，不只是重述圖表。
- 專業名詞首次出現時，以精簡白話解釋，並保留正確定義。

### 判斷｜代表什麼狀態

- 使用該區塊可取得且相關的其他證據交叉檢查。
- 清楚指出互相支持、互相背離及尚未確認的訊號。
- 區分「觀察到的現象」與「推論出的結論」；單一漲跌、法人流量或指標不能直接證明趨勢。
- 證據不足時明確說明限制，不得宣稱已完成交叉驗證。

### 操作｜接下來怎麼觀察

- 提供具體的下一個觀察重點、價位或條件。
- 方向性劇本須交代**觸發、確認、失效**三項條件；區分觸及與有效突破／跌破，必要時要求守穩、回測或反抽確認。
- 說明何時等待、不追價、降低信心或取消劇本。
- 若區塊只提供背景資訊，明確說明尚未構成進場條件，不得虛構操作建議。

### 共通品質要求

1. **交叉驗證**：優先使用兩項以上相關證據；只有單一證據時明示信心有限。
2. **反證並陳**：不可只挑選支持既有 Bias 的訊號；須交代背離與未成立條件。
3. **口徑一致**：不可混用不同法人群、不同時間區間、不同單位，或存量與流量。
4. **不確定性透明**：區分真實值、衍生值、代理／估算值、缺值及過期資料；缺值不可當零，未觀察到不可寫成不存在。
5. **結論強度匹配證據**：資料不足、樣本有限或訊號衝突時降低語氣強度，優先等待。
6. **避免冗文**：同一數字不必在多處重複；每段文字應補充新的意義、交叉關係或決策條件。用精簡語句說清楚，不堆疊術語與形容詞。

## 6. 綜合分析：跨市場決策鏈

綜合分析的核心流程固定為：

**三市場籌碼與選擇權力道 → 多空因子與市場關係 → Bias 與日夜盤情境 → 交易計畫與風險條件。**

### 三市場比較口徑

- 優先以同一法人群比較現貨外資、期貨外資日／夜盤淨交易、選擇權外資日／夜盤淨交易。
- 全體法人合計可作背景資訊，不可與單一外資群混成同一方向投票。
- 期貨 OI 是部位存量；日／夜盤淨交易是時段流量，兩者必須分開。
- 選擇權口數與契約金額代理值是不同統計口徑；同一法人方向背離時須揭露，不得擇一當成完整確認。
- 方向共識至少需要兩個可用市場訊號同向且沒有反向訊號；可用市場少於兩個或資料不足時，不形成方向共識。第三市場缺值時可說明為有限資料下的觀察。
- 三市場訊號只提供籌碼背景；價格關鍵位突破／跌破及後續確認仍是交易觸發條件。

### 因子、Bias 與相關性

- 說明 Bias 的中性基準、有效因子數及方向貢獻的統計範圍。
- 圖表若只顯示部分因子，必須標明是可見子集合，不得把其加總稱為全部因子貢獻。
- Bias 是背景評分，不是勝率、預測機率或單獨進場訊號。
- 相關性是樣本期間內的統計關係，不代表因果或預測能力；須揭露有效樣本數及穩定性限制。
- 缺值與「有值但不參與方向評分」必須區分；Gamma Flip 等價位缺值不得以 0 畫成真實價位。

### 日夜盤與交易計畫

- 清楚區分日盤價格、夜盤自身漲跌、夜盤相對日盤收盤變化及日夜盤流量，不可互相替代。
- 三劇本與交易計畫須一致：區間內觀察；偏多／偏空候選須有相應關鍵價位突破／跌破及確認條件。
- 交易計畫需整合三市場證據、因子背景、日夜盤價格關係、觸發條件、確認條件、失效條件及風險控制。
- 未有可驗證依據時，不得虛構停損點數、回測勝率或固定波動距離；明確說明實際部位與風險額度仍須另行設定。
- 綜合分析負責跨市場整合；其他分頁以各自市場／資料域的深入解讀為主，避免複製整段三市場結論。

## 7. 分頁職責與專項規則

- **期貨**：深入解讀期貨日盤價格、夜盤自身價格、相對日盤變化、基差、法人 OI 存量、日夜盤淨交易流量及夜盤劇本。日盤流量對照日盤相對前結算變化；夜盤流量對照夜盤自身收盤減開盤。跨盤收盤價差不得冒充夜盤自身漲跌。只有當期 OI、缺乏同口徑前期資料時，不得推論當日加碼／減碼。
- **選擇權**：清楚區分成交量、OI、日夜盤淨交易口數、契約金額代理值及模型估算價位；Call／Put Wall、Gamma Wall、Gamma Flip、Max Pain 的用途與限制不得混為一談。模型估算不可描述為官方持倉或確定支撐／壓力。
- **現貨／重要市場**：說明各資料的市場範圍、比較基準及單位；不可將不同市場或不同幣別的數字直接比較。
- **總覽**：摘要當日重要訊號與風險，不得產生與各專業分頁矛盾的新結論。

## 8. 圖表、單位與 UI

- 依 `docs/DASHBOARD_UNIT_STANDARD.md` 定義來源單位、標準單位及顯示單位；不可猜測單位。
- KPI、表格及文字須有明確單位；圖表可在軸、圖例或緊鄰備註標示，避免逐筆標籤造成擁擠。
- 混合單位圖表須逐數列標示；縮放值須說明換算方向與倍率。
- 圖表數值必須來自實際 Dashboard data payload，不得另放互相矛盾的硬編碼市場數字。
- 台股慣例：紅色代表上漲／多方，綠色代表下跌／空方。
- 缺值、錯誤、過期及載入失敗須清楚呈現；不得以 0 或假資料填補。
- 桌面、平板、手機均須檢查文字換行、裁切、圖例、數值標籤及重疊；維持既有 V9 Pro 版型，除非使用者明確要求改版。

## 9. 開發、測試與驗收

複雜任務採 Supervisor／Worker／Auditor 分工。若只有單一模型，必須如實稱為自我審查，不得宣稱獨立多模型審核。

1. 確認需求、修改範圍、檔案清單與驗收標準。
2. 檢查目前分支、檔案狀態及修改前差異。
3. 僅修改授權範圍，檢查 diff，避免連帶改動。
4. 執行與修改範圍相符的語法、資料、Build、Browser Audit 或部署測試。
5. Auditor 對照需求、程式與實際證據；發現缺陷先修正再複驗。
6. 區分自動化測試與人工畫面驗收；Actions 成功不代表數據正確或市場判讀合理。

狀態定義：
- **PASS**：有對應證據且驗收通過。
- **FAIL**：已確認不符合。
- **BLOCKED**：受未解決外部條件或資料定義阻擋。
- **NOT TESTED**：尚未執行或沒有足夠證據。

UI-only 任務若完整 Build Workflow 會執行資料層或 Builder，且本輪未授權資料層操作，應使用 UI-only Audit；不可把 UI-only Audit 描述成資料層驗證或正式部署。

## 10. 交付與回報

只回報與使用者指定任務相關的結果，清楚列出：
- 修改檔案與實際變更。
- 已執行的測試及其證據。
- PASS／FAIL／BLOCKED／NOT TESTED。
- 尚未完成事項與必要風險。

只有實際成功建立的 commit、部署或檔案，才能宣稱完成並提供連結。不得以「已修改」代替「已驗證」。
